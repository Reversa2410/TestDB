================================================================================
 UNIDAD V - GESTION DE CLIENTES (ARQUITECTURA CLIENTE-SERVIDOR)
 Guia completa de replicacion paso a paso
================================================================================

 Stack usado : SQL Server + Java (Swing) con el driver JDBC oficial
 Resultado   : app de escritorio que se conecta a un SGBD real, registra
               clientes y los consulta en una grilla.

 Esta guia es autocontenida: siguiendo los pasos y copiando los archivos
 del apartado 7 se reconstruye el proyecto completo desde cero.

 No hace falta Maven ni un IDE: basta con el JDK y los dos .bat incluidos.
 Quien prefiera IntelliJ o Eclipse puede abrir el pom.xml.


================================================================================
 1. QUE PIDE LA PRACTICA (resumen)
================================================================================

 A. Base de datos (30 pts)
    BD "BD_Comercializadora" con tabla "Clientes":
      IdCliente       INT           PK, autoincremental
      Nombres         VARCHAR(80)   obligatorio
      Apellidos       VARCHAR(80)   obligatorio
      Identificacion  VARCHAR(20)   unico
      Telefono        VARCHAR(15)   obligatorio
      Correo          VARCHAR(100)  unico
      Direccion       VARCHAR(150)  obligatorio
      Estado          BIT           valor por defecto activo
    Minimo 5 registros de prueba y una consulta que los liste.

 B. Aplicacion / Presentation Tier (35 pts)
    Ventana "Gestion de Clientes" con boton Guardar, boton Consultar,
    grilla de resultados, validacion de campos obligatorios y mensajes
    de exito y de error.

 C. Cadena de conexion (25 pts)
    Servidor + puerto + base de datos + usuario y clave, dentro de la app,
    con una prueba de conexion.

 D. Pruebas (10 pts)
    Abrir la app, comprobar conexion, registrar un cliente desde la interfaz,
    consultarlo y verificarlo directamente en el SGBD.

 NO hace falta: UPDATE, DELETE, login, API REST, capas, procedimientos
 almacenados. Si se permiten componentes visuales y asistentes del IDE.
 La conexion debe ser real, no simulada.


================================================================================
 2. REQUISITOS PREVIOS
================================================================================

 1) SQL Server instalado y con el servicio corriendo.
    Comprobar en PowerShell:

        Get-Service MSSQLSERVER

    Debe decir "Running". Si la instancia es SQL Server Express, el servicio
    se llama MSSQL$SQLEXPRESS y el servidor es "localhost\SQLEXPRESS".

 2) JDK 17 o superior. Comprobar:

        java -version

    Si el comando no existe, el JDK esta instalado pero no en el PATH.
    No es un problema: compilar.bat y ejecutar.bat lo buscan solos en
    C:\Program Files\Java, en Eclipse Adoptium y en JAVA_HOME.

 3) Herramienta sqlcmd (viene con SQL Server) o SQL Server Management Studio,
    para ejecutar el script y para comprobar los registros al final.

 4) El driver JDBC de Microsoft. Ya viene en la carpeta lib del proyecto.
    Si hay que descargarlo de nuevo, son dos archivos de Maven Central:

      https://repo1.maven.org/maven2/com/microsoft/sqlserver/mssql-jdbc/13.6.2.jre11/mssql-jdbc-13.6.2.jre11.jar
      https://repo1.maven.org/maven2/com/microsoft/sqlserver/mssql-jdbc_auth/13.6.2.x64/mssql-jdbc_auth-13.6.2.x64.dll

    El .jar es el driver. El .dll solo hace falta para la autenticacion de
    Windows; con usuario y contrasena de SQL Server no se usa.


================================================================================
 3. HABILITAR TCP/IP EN SQL SERVER  (PASO IMPRESCINDIBLE)
================================================================================

 Este es el paso donde se atasca casi todo el mundo al usar Java.

 El driver JDBC solo se comunica por TCP/IP. SQL Server trae ese protocolo
 DESHABILITADO por defecto en muchas instalaciones y, mientras lo este, la
 aplicacion fallara con este mensaje:

     No se pudo realizar la conexion TCP/IP al host localhost, puerto 1433.
     Error: "Connection refused..."

 Que no confunda: sqlcmd y las aplicaciones .NET pueden conectarse igual,
 porque usan memoria compartida cuando el servidor esta en el mismo equipo.
 Java no tiene esa opcion.

 Para habilitarlo:

   1. Abrir "Administrador de configuracion de SQL Server"
      (SQLServerManager*.msc desde Ejecutar, si no aparece en el menu).
   2. Configuracion de red de SQL Server -> Protocolos de <INSTANCIA>.
   3. Clic derecho en TCP/IP -> Habilitar.
   4. Doble clic en TCP/IP -> pestaña Direcciones IP -> al final, en IPAll:
         Puertos TCP dinamicos: (vacio)
         Puerto TCP          : 1433
   5. Servicios de SQL Server -> clic derecho en el servicio -> Reiniciar.

 Comprobar que quedo escuchando:

     Get-NetTCPConnection -State Listen -LocalPort 1433

 Debe aparecer al menos una linea. Si el servidor esta en otro equipo, hay
 que abrir ademas el puerto 1433 en el firewall.

 PASO 1 - Crear la estructura de carpetas

     Del apartado 7, dentro de app-java:

         conexion.properties
         compilar.bat

         src\gestionclientes\Cliente.java

         src\gestionclientes\ClientesRepositorio.java
         src\gestionclientes\VentanaClientes.java
         src\gestionclientes\LimiteTexto.java
         src\gestionclientes\Main.java

 PASO 5 - Ajustar la cadena de conexion

     Abrir conexion.properties y dejar en jdbc.url la que corresponda.
     Casos tipicos:

       Instancia por defecto, autenticacion de Windows:
         jdbc:sqlserver://localhost;databaseName=BD_Comercializadora;integratedSecurity=true;encrypt=true;trustServerCertificate=true

       Instancia SQL Express (la barra invertida va DOBLE en un .properties):
         jdbc:sqlserver://localhost\\SQLEXPRESS;databaseName=BD_Comercializadora;integratedSecurity=true;encrypt=true;trustServerCertificate=true

       Con usuario y contrasena de SQL Server:
         jdbc.url=jdbc:sqlserver://localhost:1433;databaseName=BD_Comercializadora;encrypt=true;trustServerCertificate=true
         jdbc.usuario=sa
         jdbc.clave=TuClave

       Servidor remoto:
         jdbc:sqlserver://192.168.1.50:1433;databaseName=BD_Comercializadora;encrypt=true;trustServerCertificate=true

     trustServerCertificate=true es necesario porque el driver cifra la
     conexion por defecto y el certificado de un servidor local no esta
     firmado por una entidad de confianza.

 PASO 6 - Compilar

     cd app-java
     compilar.bat

     Debe decir "Compilacion correcta". Se crea la carpeta bin con los
     .class; esa carpeta no se entrega, se regenera sola.

 PASO 7 - Probar la conexion sin abrir la ventana

     ejecutar.bat --prueba

     Salida esperada:

         Cadena de conexion : jdbc:sqlserver://localhost;databaseName=...
         Servidor / BD      : NOMBRE-EQUIPO / BD_Comercializadora
         Clientes antes     : 5
         Insertado IdCliente: 6
         Clientes despues   : 6
         RESULTADO: OK

     Con JDK 22 o superior salen ademas unos avisos "WARNING: A restricted
     method in java.lang.System has been called". Son del JDK al cargar la
     DLL de autenticacion de Windows: no son un error y se pueden ignorar.

     Si da FALLO, el mensaje dice el motivo. Ver el apartado 6.

 PASO 8 - Ejecutar la aplicacion

     ejecutar.bat

     Al abrir, la barra inferior debe decir en verde:
         "OK - 5 cliente(s) recuperado(s) desde la base de datos."

 PASO 9 - Hacer la demostracion (punto D)

     1. Abrir la app y comprobar que la barra inferior dice OK.
     2. Llenar los campos y pulsar Guardar.
        Aparece el aviso "Registro guardado correctamente" con el Id asignado.
     3. Pulsar Consultar: el nuevo cliente aparece en la grilla.
     4. Verificar el registro directamente en el SGBD:

            sqlcmd -S localhost -E -C -d BD_Comercializadora -Q "SELECT * FROM dbo.Clientes"

        o ejecutar ese mismo SELECT en SQL Server Management Studio.
     5. Capturar pantalla de los pasos 2, 3 y 4.

     Probar tambien los casos de error, que suman puntos en la rubrica:
       - Dejar un campo vacio y pulsar Guardar -> aviso de validacion.
       - Repetir una Identificacion o un Correo ya existente -> aviso de
         registro duplicado (lo provocan las restricciones UNIQUE).

================================================================================
 6. PROBLEMAS FRECUENTES
================================================================================

 "No se pudo realizar la conexion TCP/IP al host localhost, puerto 1433"
     TCP/IP esta deshabilitado en SQL Server. Es el caso mas comun con Java.
     Ver el apartado 3 completo.

 "El controlador no pudo establecer una conexion segura mediante SSL"
     Falta trustServerCertificate=true en jdbc.url.

 "No suitable driver found for jdbc:sqlserver://..."
     El .jar del driver no esta en el classpath. Revisar que este en lib y
     que se ejecute con ejecutar.bat, que es quien pone -cp "bin;lib\*".

 "WARNING: Failed to load the sqljdbc_auth.dll"
     Falta la DLL en lib, o se esta ejecutando sin -Djava.library.path="lib",
     o la DLL es de 32 bits y el JDK de 64. Alternativa rapida: usar usuario
     y contrasena de SQL Server, que no necesita la DLL.

 "Login failed for user 'sa'"
     La autenticacion mixta esta desactivada o la clave es otra. Lo mas
     rapido en un equipo propio es la autenticacion de Windows.

 "Cannot open database BD_Comercializadora"
     El script no se ejecuto, o se ejecuto contra otra instancia distinta
     de la que apunta la cadena de conexion.

 "Invalid object name 'dbo.Clientes'"
     La base existe pero la tabla no: volver a ejecutar el script completo.

 "Violation of UNIQUE KEY constraint"
     Es el comportamiento correcto: ya existe un cliente con esa
     identificacion o ese correo. La app lo traduce a un aviso legible.

 "No se encontro un JDK. Instale uno o defina la variable JAVA_HOME."
     Lo dice compilar.bat cuando no encuentra javac. Instalar un JDK (no
     solo un JRE) o definir JAVA_HOME apuntando a la carpeta del JDK.

 "error: invalid source release" al compilar
     El JDK es anterior a 17. El codigo usa bloques de texto y switch con
     flechas. Actualizar el JDK o bajar esas construcciones a sintaxis vieja.

 La ventana abre pero la barra inferior esta en rojo
     El problema es la cadena de conexion, no el codigo. El cuadro de error
     muestra la cadena que se intento usar, con la contrasena enmascarada.

 "No se encontro conexion.properties"
     El archivo debe estar en la carpeta desde la que se ejecuta la app.
     ejecutar.bat hace "cd /d %~dp0" justo para eso.

/* =========================================================
   Unidad V - Arquitectura Cliente-Servidor
   Script de creacion: BD_Comercializadora (SQL Server)
   ========================================================= */

-- 1. Crear la base de datos
IF DB_ID('BD_Comercializadora') IS NULL
    CREATE DATABASE BD_Comercializadora;
GO

USE BD_Comercializadora;
GO

-- 2. Crear la tabla Clientes (3. llave primaria y 4. restricciones incluidas)
IF OBJECT_ID('dbo.Clientes', 'U') IS NOT NULL
    DROP TABLE dbo.Clientes;
GO

CREATE TABLE dbo.Clientes
(
    IdCliente      INT           IDENTITY(1,1) NOT NULL,
    Nombres        VARCHAR(80)   NOT NULL,
    Apellidos      VARCHAR(80)   NOT NULL,
    Identificacion VARCHAR(20)   NOT NULL,
    Telefono       VARCHAR(15)   NOT NULL,
    Correo         VARCHAR(100)  NOT NULL,
    Direccion      VARCHAR(150)  NOT NULL,
    Estado         BIT           NOT NULL CONSTRAINT DF_Clientes_Estado DEFAULT (1),

    CONSTRAINT PK_Clientes            PRIMARY KEY (IdCliente),
    CONSTRAINT UQ_Clientes_Identif    UNIQUE (Identificacion),
    CONSTRAINT UQ_Clientes_Correo     UNIQUE (Correo)
);
GO

-- 5. Insertar registros de prueba (minimo cinco)
INSERT INTO dbo.Clientes (Nombres, Apellidos, Identificacion, Telefono, Correo, Direccion)
VALUES
    ('Ana',    'Lopez',    '1001001001', '3001112233', 'ana.lopez@correo.com',    'Calle 10 # 5-20'),
    ('Carlos', 'Ruiz',     '1002002002', '3002223344', 'carlos.ruiz@correo.com',  'Avenida 7 # 45-10'),
    ('Maria',  'Gomez',    '1003003003', '3003334455', 'maria.gomez@correo.com',  'Carrera 15 # 80-30'),
    ('Jorge',  'Martinez', '1004004004', '3004445566', 'jorge.martinez@correo.com','Diagonal 22 # 12-05'),
    ('Lucia',  'Pena',     '1005005005', '3005556677', 'lucia.pena@correo.com',   'Transversal 9 # 33-40');
GO

-- 6. Consulta de verificacion: todos los clientes registrados
SELECT IdCliente,
       Nombres,
       Apellidos,
       Identificacion,
       Telefono,
       Correo,
       Direccion,
       Estado
FROM dbo.Clientes
ORDER BY IdCliente;
GO

@echo off
REM Compila el proyecto sin necesidad de Maven ni IDE.
setlocal enabledelayedexpansion
cd /d "%~dp0"

REM --- Localizar el JDK -------------------------------------------
set "JDKBIN="
for %%I in (javac.exe) do if not "%%~$PATH:I"=="" set "JDKBIN=%%~dp$PATH:I"
if not defined JDKBIN if defined JAVA_HOME if exist "%JAVA_HOME%\bin\javac.exe" set "JDKBIN=%JAVA_HOME%\bin\"
if not defined JDKBIN for /d %%D in ("C:\Program Files\Java\jdk*") do if exist "%%D\bin\javac.exe" set "JDKBIN=%%D\bin\"
if not defined JDKBIN for /d %%D in ("C:\Program Files\Eclipse Adoptium\jdk*") do if exist "%%D\bin\javac.exe" set "JDKBIN=%%D\bin\"
if not defined JDKBIN for /d %%D in ("C:\Program Files\Microsoft\jdk*") do if exist "%%D\bin\javac.exe" set "JDKBIN=%%D\bin\"
if not defined JDKBIN (
    echo No se encontro un JDK. Instale uno o defina la variable JAVA_HOME.
    exit /b 1
)

if not exist "bin" mkdir "bin"

set "FUENTES="
for /r "src" %%F in (*.java) do set FUENTES=!FUENTES! "%%F"
if not defined FUENTES (
    echo No se encontraron archivos .java dentro de src.
    exit /b 1
)

echo Compilando con "%JDKBIN%javac"
"%JDKBIN%javac" -encoding UTF-8 -d bin -cp "lib\*"!FUENTES!
if errorlevel 1 (
    echo.
    echo FALLO LA COMPILACION.
    exit /b 1
)

echo Compilacion correcta. Ahora ejecute ejecutar.bat

package gestionclientes;

import java.io.IOException;
import java.io.InputStream;
import java.io.InputStreamReader;
import java.io.Reader;
import java.io.UncheckedIOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;
import java.util.Properties;

/**
 * Requerimiento C: lectura de la cadena de conexion desde conexion.properties
 * y apertura de conexiones contra el SGBD.
 */
public final class Conexion {

    private static final String ARCHIVO = "conexion.properties";

    private static String url;
    private static String usuario;
    private static String clave;

    private Conexion() {
    }

    private static synchronized void cargar() {
        if (url != null) {
            return;
        }

        Properties p = new Properties();

        // Se busca primero junto al programa y, si no esta, dentro del propio jar.
        Path local = Path.of(ARCHIVO);
        try {
            if (Files.exists(local)) {
                try (Reader r = Files.newBufferedReader(local, StandardCharsets.UTF_8)) {
                    p.load(r);
                }
            } else {
                try (InputStream in = Conexion.class.getClassLoader().getResourceAsStream(ARCHIVO)) {
                    if (in == null) {
                        throw new IllegalStateException(
                                "No se encontro " + ARCHIVO + " con la cadena de conexion.");
                    }
                    p.load(new InputStreamReader(in, StandardCharsets.UTF_8));
                }
            }
        } catch (IOException e) {
            throw new UncheckedIOException("No se pudo leer " + ARCHIVO, e);
        }

        url = p.getProperty("jdbc.url", "").trim();
        if (url.isEmpty()) {
            throw new IllegalStateException(ARCHIVO + " no contiene la clave 'jdbc.url'.");
        }

        usuario = p.getProperty("jdbc.usuario", "").trim();
        clave = p.getProperty("jdbc.clave", "").trim();
    }

    /** Abre una conexion nueva contra el servidor de base de datos. */
    public static Connection abrir() throws SQLException {
        cargar();
        if (usuario.isEmpty()) {
            // Autenticacion de Windows: las credenciales van dentro de la URL.
            return DriverManager.getConnection(url);
        }
        return DriverManager.getConnection(url, usuario, clave);
    }

    /** Version segura para mostrar en pantalla (oculta la contrasena). */
    public static String cadenaParaMostrar() {
        cargar();

        StringBuilder sb = new StringBuilder();
        for (String parte : url.split(";")) {
            if (parte.isBlank()) {
                continue;
            }
            String nombre = parte.split("=")[0].trim().toLowerCase();
            sb.append(nombre.equals("password") ? "password=********" : parte.trim()).append(';');
        }

        if (!usuario.isEmpty()) {
            sb.append(" [usuario=").append(usuario).append("; clave=********]");
        }
        return sb.toString();
    }
}

package gestionclientes;

import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.sql.Statement;
import java.sql.Types;
import java.util.ArrayList;
import java.util.List;

/**
 * Acceso a datos: unico punto donde la aplicacion habla con el SGBD.
 */
public class ClientesRepositorio {

    /** Codigos de SQL Server para violacion de restriccion UNIQUE. */
    public static boolean esDuplicado(SQLException e) {
        return e.getErrorCode() == 2601 || e.getErrorCode() == 2627;
    }

    /** Prueba de conexion (Requerimiento C, actividad 6). */
    public String probarConexion() throws SQLException {
        String sql = "SELECT @@SERVERNAME + ' / ' + DB_NAME();";
        try (Connection cn = Conexion.abrir();
             PreparedStatement cmd = cn.prepareStatement(sql);
             ResultSet r = cmd.executeQuery()) {

            return r.next() ? r.getString(1) : "(desconocido)";
        }
    }

    /** Consulta todos los clientes registrados. */
    public List<Cliente> consultar() throws SQLException {
        String sql = """
                SELECT IdCliente, Nombres, Apellidos, Identificacion,
                       Telefono, Correo, Direccion, Estado
                FROM dbo.Clientes
                ORDER BY IdCliente""";

        List<Cliente> lista = new ArrayList<>();

        try (Connection cn = Conexion.abrir();
             PreparedStatement cmd = cn.prepareStatement(sql);
             ResultSet r = cmd.executeQuery()) {

            while (r.next()) {
                Cliente c = new Cliente();
                c.setId(r.getInt(1));
                c.setNombres(r.getString(2));
                c.setApellidos(r.getString(3));
                c.setIdentificacion(r.getString(4));
                c.setTelefono(r.getString(5));
                c.setCorreo(r.getString(6));
                c.setDireccion(r.getString(7));
                c.setEstado(r.getBoolean(8));
                lista.add(c);
            }
        }

        return lista;
    }

    /** Inserta un cliente y devuelve el IdCliente generado. */
    public int guardar(Cliente c) throws SQLException {
        String sql = """
                INSERT INTO dbo.Clientes
                    (Nombres, Apellidos, Identificacion, Telefono, Correo, Direccion, Estado)
                VALUES
                    (?, ?, ?, ?, ?, ?, ?)""";

        try (Connection cn = Conexion.abrir();
             PreparedStatement cmd = cn.prepareStatement(sql, Statement.RETURN_GENERATED_KEYS)) {

            // Parametros: evitan inyeccion SQL y respetan los tipos de la tabla.
            cmd.setString(1, c.getNombres());
            cmd.setString(2, c.getApellidos());
            cmd.setString(3, c.getIdentificacion());
            cmd.setString(4, c.getTelefono());
            cmd.setString(5, c.getCorreo());
            cmd.setString(6, c.getDireccion());
            cmd.setObject(7, c.isEstado(), Types.BIT);

            cmd.executeUpdate();

            try (ResultSet claves = cmd.getGeneratedKeys()) {
                return claves.next() ? claves.getInt(1) : 0;
            }
        }
    }
}

package gestionclientes;

import javax.swing.text.AttributeSet;
import javax.swing.text.BadLocationException;
import javax.swing.text.PlainDocument;

/**
 * Impide escribir mas caracteres de los que admite la columna de la tabla.
 * Equivale a la propiedad MaxLength de un cuadro de texto.
 */
public class LimiteTexto extends PlainDocument {

    private final int maximo;

    public LimiteTexto(int maximo) {
        this.maximo = maximo;
    }

    @Override
    public void insertString(int desplazamiento, String texto, AttributeSet atributos)
            throws BadLocationException {

        if (texto == null) {
            return;
        }
        if (getLength() + texto.length() <= maximo) {
            super.insertString(desplazamiento, texto, atributos);
        }
    }
}

            return COLUMNAS.length;

        public String getColumnName(int col) {

        public Class<?> getColumnClass(int col) {

                case 0 -> Integer.class;

                default -> String.class;

                case 0 -> c.getId();
                case 1 -> c.getNombres();
                case 2 -> c.getApellidos();
                case 3 -> c.getIdentificacion();
                case 4 -> c.getTelefono();
                case 5 -> c.getCorreo();
                case 6 -> c.getDireccion();
                case 7 -> c.isEstado();
                default -> "";
            };
        }

================================================================================
 8. COMO FUNCIONA, EN UNA PAGINA
================================================================================

 El flujo que pide la practica es este, y en el codigo se ve asi:

   Presentation Tier          VentanaClientes.java
   (formulario Swing)         recoge los datos y valida que no haya vacios
          |
          v
   Connection String          conexion.properties + Conexion.java
   (servidor + BD +           una sola URL JDBC, leida al arrancar
    credenciales)
          |
          v
   Database Server            ClientesRepositorio.java
   (SGBD)                     abre la Connection y ejecuta INSERT o SELECT

 Cuatro detalles que valen puntos y conviene saber explicar:

 1) PreparedStatement en vez de concatenar texto.
    El INSERT usa ? y luego setString(1, ...), en lugar de pegar los valores
    dentro de la cadena SQL. Evita la inyeccion SQL y respeta los tipos y
    longitudes de las columnas.

 2) getGeneratedKeys().
    Despues del INSERT se pide el Id que SQL Server acaba de generar, y por
    eso la app puede mostrar "IdCliente asignado: 6". Es la prueba de que el
    registro se guardo en el servidor y no solo en memoria.

 3) try-with-resources.
    "try (Connection cn = Conexion.abrir(); ...)" cierra la conexion y el
    statement al terminar el bloque, aunque se lance una excepcion.

 4) AbstractTableModel.
    La JTable no sabe nada de la clase Cliente: el modelo ModeloClientes
    traduce la lista a filas y columnas, y getColumnClass hace que la
    columna Estado se pinte como casilla de verificacion.

 Diferencias con la version anterior en C#, por si alguien compara:

   C# / WinForms                      Java / Swing
   ------------------------------     ------------------------------
   appsettings.json                   conexion.properties
   SqlConnection                      Connection (DriverManager)
   SqlCommand + parametros            PreparedStatement + ?
   SCOPE_IDENTITY()                   getGeneratedKeys()
   DataGridView + BindingList         JTable + AbstractTableModel
   MessageBox.Show                    JOptionPane.showMessageDialog
   using var                          try-with-resources
   Conecta por memoria compartida     Exige TCP/IP habilitado

 El script SQL es exactamente el mismo en las dos versiones.
